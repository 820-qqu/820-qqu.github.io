Hexo + Git 命令速查

日常真正会敲的就十几条命令，其余全是排错时的救火队。这份按「每天用」到「偶尔才动」排序，所有命令默认在博客根目录执行（本机是 D:\zhangjunhaoCODE\projects\myblog）。

1. 环境检查

命令 看什么
hexo -v Hexo 与 Node 版本（本站 8.1.2 / Node v22.20.0）
node -v 必须 ≥ 20.19，低了 Hexo 8 起不来
npm -v 装依赖时用
git --version git 版本，也顺带证明 git 能跑

本机是 PowerShell 5.1，hexo new "中文标题" 会把中文参数按 GBK 传坏。文件名一律用英文/拼音，中文标题写进 front-matter 的 title:。

2. Hexo 命令

命令 作用
hexo new my-post 新建文章到 source\_posts\，并自动建同名图片文件夹
hexo new page about 新建独立页面 → source\about\index.md，发布后是 /about/
hexo new draft idea 新建草稿到 source\_drafts\，不会发布
hexo publish idea 草稿转正式，移到 source\_posts\
hexo s 本地预览 → http://localhost:4000，会一直占着窗口
hexo s -p 5000 4000 被占用时换端口
hexo clean 删掉 db.json 和 public\（换主题、删文章后必做）
hexo g 生成静态站到 public\
hexo d 把 public\ 强推到 Pages 仓库
hexo clean; hexo g; hexo d 一条龙，改动大时用
hexo d -g 生成并部署，等价于 hexo g; hexo d
hexo list post 列出所有文章的文件名（不是 title）
hexo config marked 看配置实际解析成什么，排查图片路径的神器

hexo init 目录名 是给全新的空目录初始化用的，这台机器上已经不需要了；同理 npm install 只在第一次或依赖变更（package.json 改了）时跑。

3. 每天走一遍的流程

3.1 写新文章

① 和 ② 都要做：只做 ① 站点更新了但源码没备份；只做 ② 白备份一场，线上没有任何变化。

场景 命令
只改文章正文 hexo g; hexo d
换了主题、删了文章、改了 _config.yml hexo clean; hexo g; hexo d
上线前的保险 Test-Path public\index.html，必须是 True

3.2 改已有的文章

不要重新 hexo new，直接改原来那个 .md：文件名不变，URL 就不变。

改了 title、categories、tags、date 这类会影响分类页/归档页的字段，要连 hexo clean 一起跑。updated 字段不写就取文件修改时间，想固定就自己填。

3.3 删文章

先 hexo list post 确认文件名，再删两样：.md 和它的同名图片文件夹。

删除必须 hexo clean，否则 db.json 和 public\ 里还留着旧页面、分类页和归档页。已经公开过的文章删掉后原链接会 404，慎删。

4. Git：源码备份

站点仓库和源码仓库是两个东西，别混：hexo d 推的是公开的 Pages 仓库（只放生成的 HTML），下面这些推的是源码仓库（Markdown + 图片 + 配置）。

4.1 双远程：Gitee 主、GitHub 镜像

远程 地址 用途
origin gitee.com/chapter-001/myblog 日常默认推送
github github.com/820-qqu/myblog 镜像备份

Gitee 私有仓库用私人令牌登录，令牌存在 Windows 凭据管理器里，不要写进 remote 地址。第一次在新机器上克隆 origin 会要求授权一次，之后 git 自己记住。

4.2 每天三条

git add . 也能用，但 -A 会连删除一起记录，删过文章时更准确。

4.3 看历史、回滚

想做什么 命令
最近 5 条提交 git log --oneline -5
带分支图的完整历史 git log --oneline --graph
某次改了什么 git show 提交号
还没暂存的差异 git diff
撤销某个文件的工作区改动 git restore 文件名
撤销最近一次提交但保留改动 git reset --soft HEAD~1
拉远程更新 git pull

git reset --hard 会连工作区改动一起丢掉，不到万不得已别用；真要用先把 git status 看清楚。

4.4 换机器

图片跟着 .md 一起在 source\_posts\ 里，克隆就下来了，不用单独拷。public\、node_modules\、db.json 都在 .gitignore 里，本来就不进仓库，hexo g 会重新生成。

6. 排错速查

现象 处理
hexo 不是内部或外部命令 没装 npm install -g hexo-cli，或装完没重开窗口
无法加载文件 hexo.ps1，因为在此系统上禁止运行脚本 Set-ExecutionPolicy -Scope CurrentUser RemoteSigned，只需一次
TypeError: Invalid URL _config.yml 的 url: 不能带尖括号，写裸地址
线上 404 / 本地 Cannot GET / Test-Path public\index.html；再确认 source\_posts\ 不是空的
图片 404 hexo config marked 看 postAsset: true；再查文件夹名是否带连字符
hexo d 推不上去 先 git ls-remote 探路，再查代理
推上去了网页没变 是不是只 hexo d 没 hexo g？浏览器 Ctrl+F5 强刷
git log 中文像乱码 只是显示问题：[Console]::OutputEncoding = [System.Text.Encoding]::UTF8

代理：系统代理端口是 127.0.0.1:7897（不是 7890）。代理软件开着时让 git 也走它，关掉后记得撤回，否则 git 会去连一个不存在的端口。

SSH（可选，比 HTTPS 少一次授权）：

公钥分别贴到 Gitee 和 GitHub 的 SSH 公钥设置里；两台机器的地址改成 git@ 开头即可，HTTPS 也能用，没必要为它折腾。
